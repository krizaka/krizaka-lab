# krizaka-motion — audit against the Krizaka standards (2026-10-20)

Scope: `main` at 9c1d106 (built by Antigravity, 6 commits), against krizaka.com `AGENTS.md` (§2.1 the home, §4 one motion
system, §4.1 blocks), krizaka-ui `AGENTS.md` / `packages/ui/AGENTS.md` and `docs/RELEASING.md`, and the motion system of
`@krizaka/ui` (`MotionObserver`, `reveal`, `NumberTicker`, `motion.css`).

## Verdict

**krizaka-motion stays a lab; its generic piece moves into Krizaka UI.** The « Orazaka Neural Pipeline Flow » is
rebuilt as **`@krizaka/ui/engine-flow`** (`EngineFlow`) in SVG + CSS on the one motion system, and krizaka.com's home
uses that. `@krizaka/motion` is **not published on npm** (`"private": true`): the experimental canvas demos (voice
presence, holographic HUD, liquid glass, neural lattice) keep living here, played on GitHub Pages.

Why this path, and not « publish `@krizaka/motion` with the family »:

- **One motion system** (krizaka.com `AGENTS.md` §4): « no second conductor, no permanent requestAnimationFrame, no
  canvas … missing generic primitives go to krizaka-ui ». A second motion package with its own controller is exactly
  what that rule forbids for the sites.
- **The flow does not need a canvas.** Conduits are SVG paths; photons are zero-length dashes whose `stroke-dashoffset`
  slides (CSS animation). That gets, for free: the off-screen pause (`[data-offscreen]` from `MotionObserver`), the
  settle hold (`kz-loop`), a still frame under reduced motion, crisp rendering at any DPR, the brand tokens through
  CSS variables in both themes, real buttons for the nodes, and server rendering (no layout shift).
- **Cheapest coherent path**: one entry in an existing package (2.2 kB gzip), released by the documented procedure
  with its registry page on ui.krizaka.com, instead of a new package, a new release line, provenance setup and a
  second documentation site.
- The canvas demos are real experiments, not primitives: none passes the site rules yet (below). They stay here until
  one is needed by a product; then it moves into Krizaka UI the same way.

## The GitHub Pages demo was broken — why

`https://krizaka.github.io/krizaka-motion/` answered 404: **no deployment ever succeeded**.

1. **The real failure**: the deploy job died at « Setup pnpm » — `pnpm/action-setup`'s installer crashed with
   `onlyBuiltDependencies?.sort is not a function`, because `.npmrc` held `only-built-dependencies=esbuild` (a string
   where pnpm expects a list). `pnpm-workspace.yaml` held `allowBuilds:` (a pnpm 11+ key) and `package.json` named no
   `packageManager`, so CI and the Mac ran different pnpm majors (10 vs 12).
2. Every other run was **cancelled while queued**: the `pages` concurrency group keeps one pending run, and the org's
   runners were saturated that night, so each push cancelled the previous deploy before it started.
3. A leftover **`gh-pages` branch** (an earlier attempt) triggered « pages build and deployment » runs that were also
   cancelled, leaving the site in the `errored` state although the source is the workflow.

The base path and the client routes were already right: Vite `base: "./"` (relative assets), one folder per REST route
(`scripts/generate-routes.mjs`, `../assets/` rewritten), and a `404.html` that sends any other deep link to
`/krizaka-motion/?/<route>`.

**Fixed** (PR « fix(pages) »): `.npmrc` removed; `pnpm-workspace.yaml` with `onlyBuiltDependencies: [esbuild]`;
`packageManager: pnpm@10.34.6` (the family's); the deploy split into a `build` job (read-only) and a `deploy` job (Pages
write), SHA-pinned, with a check that `index.html`, `404.html` and a route folder exist; the app now restores the clean
REST path after the 404 hop (`cleanSpaRedirect`, tested); the stale `gh-pages` branch deleted.
